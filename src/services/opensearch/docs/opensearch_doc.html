OpenSearch Module — Modular Workflow Documentation

The src/services/opensearch package is the keyword (lexical) search backend of the RAG system. It wraps the official opensearch-py driver and provides everything needed to store arXiv papers and retrieve them by BM25 relevance. It owns four responsibilities:

  1. Defining the index schema (field types and text analyzers) for arXiv papers.
  2. Building structured, boosted, highlighted search queries.
  3. Managing the index lifecycle and executing reads/writes against the cluster.
  4. Exposing a single cached client instance to the rest of the application.
Where it sits: the upstream pipeline (arXiv client → PDF parser → metadata) produces paper documents. This module is the sink that indexes them and the source that later answers keyword queries. It is the BM25 half of a hybrid (lexical + vector) retrieval design.

Architectural Overview

The package is split into 4 single-responsibility modules. Dependencies flow in one direction — the client composes the schema and the query builder; the factory wraps the client; nothing depends on the factory except the outside world.

Component 1 — Index Schema (index_config.py)

Purpose: declare how OpenSearch stores and tokenizes each field. This is pure configuration — no logic — so the schema can be reviewed and version-controlled independently of the client code.

Index-level settings

SettingValueWhy
number_of_shards1Single-node / dev-sized index; avoids cross-shard scoring skew on small corpora
number_of_replicas0No redundancy needed for a local/dev cluster — keeps health green on one node

Custom analyzers

AnalyzerDefinitionEffect
standard_analyzerstandard + _english_ stopwordsLight normalization — used for authors where stemming would distort names
text_analyzercustom: standard tokenizer + lowercase → stop → snowballAggressive: lowercases, drops stopwords, and snowball-stems tokens (learning→learn) so morphological variants match. Used for title, abstract, raw_text

Field mappings

"dynamic": "strict" — OpenSearch rejects any document containing a field not declared below. This is a guardrail: a typo'd field name fails loudly at index time instead of silently creating an unmapped field.
FieldTypeNotes
arxiv_idkeywordExact-match identifier; also used as the document _id
titletext (text_analyzer) + .keyword sub-fieldFull-text searchable; .keyword sub-field allows exact match / sorting
authorstext (standard_analyzer) + .keywordStored as a comma-joined string (see client), name-preserving analysis
abstracttext (text_analyzer)Primary relevance signal alongside title
categorieskeywordFaceting / filtering (e.g. cs.AI) — exact terms, not analyzed
raw_texttext (text_analyzer)Full parsed PDF body; mapped for future full-document search
pdf_urlkeywordStored verbatim, not searched
published_datedateSortable; drives "latest papers" ordering
created_at / updated_atdateIndex-management timestamps, auto-filled by the client

Component 2 — Query Builder (query_builder.py)

Purpose: translate a few simple Python arguments into the verbose OpenSearch Query DSL. Keeping this in its own class means the client never hand-builds JSON, and the query shape can be unit-tested without a live cluster.

PaperQueryBuilder.build() assembles five pieces into one request body:

{
  "query":  _build_query(),          # bool: must (text) + filter (categories)
  "size":   ,
  "from":   ,
  "track_total_hits": true,
  "_source": _build_source_fields(), # which stored fields to return
  "highlight": _build_highlight(),   # snippet config
  "sort":   _build_sort()            # optional, only when added
}

1. Text query — _build_text_query()

A multi_match across boosted fields:

"multi_match": {
  "query": query,
  "fields": ["title^3", "abstract^2", "authors^1"],
  "type": "best_fields",
  "operator": "or",
  "fuzziness": "AUTO",
  "prefix_length": 2
}
KnobMeaning
title^3 / abstract^2 / authors^1Field boosting: a hit in the title is worth 3× a hit in authors
type: best_fieldsScore = the single best-matching field (good for "which one field is most relevant")
operator: orAny query term may match — favors recall
fuzziness: AUTOTolerates typos (edit distance scaled to term length)
prefix_length: 2First 2 characters must match exactly — stops fuzzy matching from exploding on short prefixes

2. Bool assembly — _build_query() + _build_filters()

  • The text query goes in must (scored). If the query string is empty, it falls back to {"match_all": {}} so the request still returns documents.
  • categories become a terms clause in filter — filters don't affect score and are cacheable, so category narrowing is cheap.

3. Source projection — _build_source_fields()

Returns only the display fields (arxiv_id, title, authors, abstract, categories, published_date, pdf_url). Notably raw_text is excluded — no need to ship the full PDF body over the wire on every search.

4. Highlighting — _build_highlight()

FieldConfigResult
titlenumber_of_fragments: 0Returns the entire highlighted title
abstractfragment_size: 150, up to 3 fragments, <mark> tagsUp to three 150-char snippets around matches
authorswhole field, <mark> tagsFull author string with matches marked

require_field_match: false lets a term matched in one field still be highlighted in others.

5. Sorting — _build_sort()

Decision logic:
  • latest_papers=True → sort by published_date desc, then _score (recency-first).
  • Non-empty query, latest_papers=False → return None → OpenSearch sorts by BM25 relevance.
  • Empty query → sort by published_date desc (newest-first browse mode).

A module-level helper build_search_query(...) is also provided as a thin functional shortcut around the class for callers that only need a query dict.

Component 3 — Client (client.py)

OpenSearchClient is the operational core. The constructor builds an opensearchpy.OpenSearch connection (HTTP, compression on, SSL off for local dev) and resolves the target index name from Settings, falling back to the ARXIV_PAPERS_INDEX constant.

Index lifecycle

MethodBehavior
create_index(force=False)Creates the index from ARXIV_PAPERS_MAPPING. Returns False if it already exists; with force=True it deletes and recreates. RequestError and unexpected errors are caught and logged, returning False.

Write path

MethodBehavior
index_paper(paper_data)Single-document upsert. Validates arxiv_id is present; auto-fills created_at/updated_at; normalizes an authors list into a comma-joined string (matching the schema). Uses id=arxiv_id so re-indexing the same paper updates rather than duplicates, and refresh=True to make it immediately searchable.
bulk_index_papers(papers)Loops index_paper over a list and returns {"success": N, "failed": M}. A failure on one paper never aborts the batch.
Trade-off: bulk_index_papers currently iterates one document at a time (each with refresh=True) rather than using OpenSearch's _bulk API. This is simple and resilient but slower for large batches — a natural future optimization.

Read path — search_papers(...)

The headline method. It delegates all query construction to PaperQueryBuilder, executes the search, and reshapes the raw OpenSearch response into a flat, caller-friendly dict:

{
  "total": ,                 # response.hits.total.value
  "hits": [
    { ...source fields,
      "score": ,           # promoted from hit._score
      "highlights": { ... } }     # present only if OpenSearch returned them
  ]
}

Parameters mirror the builder: query, size, from_, fields, categories, track_total_hits, latest_papers. Errors degrade gracefully — a missing index returns {"total": 0, "hits": [], "error": "Index not found"} rather than raising.

Introspection & health

MethodReturns
get_index_stats()Index name, document count, store size in bytes, and cluster health status
health_check()True if cluster status is green or yellow — used by service health probes
get_cluster_info() / get_cluster_health()Raw cluster info() / health() payloads (or None on error)
get_index_mapping() / get_index_settings()Unwrap the nested OpenSearch response to return just this index's mapping / settings
Every method follows the same defensive contract: wrap the call in try/except, log the error, and return a safe sentinel (False, None, or an empty/error dict). Callers never have to handle raw opensearchpy exceptions.

Component 4 — Factory (factory.py)

Purpose: give the rest of the app one shared, lazily-constructed client.

@lru_cache(maxsize=1)
def make_opensearch_client() -> OpenSearchClient:
    settings = get_settings()
    return OpenSearchClient(host=settings.opensearch.host, settings=settings)
  • @lru_cache(maxsize=1) turns the function into a singleton — the first call constructs the client (and its underlying connection pool); every later call returns the same instance.
  • Host and settings are read from the central get_settings(), keeping configuration in one place.
  • This mirrors the other service factories in the codebase, so dependency wiring is uniform across modules.

End-to-End Sequence

Indexing (write)

Pipeline produces paper dicts
  │
  ▼
client = make_opensearch_client()      # cached singleton
client.create_index()                  # once; no-op if exists
  │
  ▼
client.bulk_index_papers(papers)
  └─ for each paper → index_paper(paper)
        │ validate arxiv_id
        │ fill created_at / updated_at
        │ join authors list → string
        ▼
     OpenSearch index (id = arxiv_id, refresh=True)
  ▼
{"success": N, "failed": M}

Searching (read)

Caller
  │ client.search_papers("graph neural networks",
  │                      size=10, categories=["cs.LG"])
  ▼
PaperQueryBuilder(...).build()
  │ multi_match title^3 / abstract^2 / authors^1
  │ + terms filter on categories
  │ + highlight + source projection + sort decision
  ▼
opensearch.search(index, body)
  ▼
reshape response
  │ total ← hits.total.value
  │ each hit → source + score + highlights
  ▼
{"total": 42, "hits": [ {arxiv_id, title, ..., score, highlights}, ... ]}

Key Design Patterns

  1. SoCSeparation of concerns — schema, query construction, operations, and instantiation each live in their own file.
  2. BuilderQuery Builder — PaperQueryBuilder isolates verbose DSL JSON behind a small typed constructor, testable without a cluster.
  3. SingletonCached factory — @lru_cache(maxsize=1) shares one connection pool across the app.
  4. DIDependency injection — Settings is passed into the client, not imported ad hoc, easing testing and reconfiguration.
  5. DefensiveFail-soft contract — every client method catches, logs, and returns a safe sentinel instead of leaking opensearchpy exceptions.
  6. ResilientBatch resilience — one bad document never aborts a bulk index run.
  7. Strict SchemaStrict mapping — dynamic: "strict" rejects unmapped fields, catching producer bugs at index time.
  8. RelevanceTuned BM25 — field boosting, fuzziness with prefix guard, and a context-aware sort policy balance precision, recall, and recency.
  9. IdempotentUpsert by ID — using arxiv_id as the document _id makes re-ingestion safe (update, not duplicate).
