ArxivClient — Modular Workflow Documentation

The ArxivClient class is an async client for the arXiv public API. It handles three responsibilities:

  1. Querying arXiv for paper metadata (by category, custom query, or ID).
  2. Parsing arXiv's Atom XML response into typed ArxivPaper objects.
  3. Downloading the PDFs of those papers to a local cache.

Layer 2 — Public Fetch API (3 entry points)

All three return List[ArxivPaper] (or single paper) and share the same pipeline: build URL → rate-limit → HTTP GET → parse XML.

fetch_papers(...) — Category-based fetch

  • Builds a search query: cat:cs.AI
  • If from_date/to_date provided, appends AND submittedDate:[YYYYMMDD0000+TO+YYYYMMDD2359]
    • 0000 = start of day, 2359 = end of day
    • Wildcards * used when only one bound is provided
  • Caps max_results at 2000 (arXiv's per-request hard limit)
  • Use case: "Give me the latest 100 cs.AI papers from yesterday"

fetch_papers_with_query(...) — Custom query string

  • Accepts any raw arXiv query (au:LeCun, ti:transformer, boolean combinations)
  • Uses a slightly more permissive safe = ":+[]*" to keep * wildcards intact
  • Use case: "Find all papers by LeCun on transformers"

fetch_paper_by_id(arxiv_id) — Single paper lookup

  • Strips version suffix: 2507.17748v1 → 2507.17748
  • Uses id_list= parameter instead of search_query=
  • Returns Optional[ArxivPaper] — None when not found (logged as warning, not raised)

Layer 3 — Rate Limiting + Network

This isn't a separate method, it's a shared pattern copy-pasted into each fetch method:

if self._last_request_time is not None:
    time_since_last = time.time() - self._last_request_time
    if time_since_last < self.rate_limit_delay:
        await asyncio.sleep(self.rate_limit_delay - time_since_last)
self._last_request_time = time.time()

Logic: "If less than rate_limit_delay seconds have passed since the last request, sleep for the remaining time."

HTTP Transport

Uses httpx.AsyncClient as a context manager (auto-closes connection):

async with httpx.AsyncClient(timeout=...) as client:
    response = await client.get(url)
    response.raise_for_status()
    xml_data = response.text

Exception Normalization

This is important — callers can catch ArxivAPIException without depending on httpx.

Layer 4 — XML Parsing

arXiv returns Atom XML feeds. Parsing happens in two stages.

Stage 1: _parse_response(xml_data) — feed-level

  • Parses XML root via ET.fromstring
  • Finds all <atom:entry> elements
  • Delegates each to _parse_single_entry
  • Catches ET.ParseError → raises ArxivParseError

Stage 2: _parse_single_entry(entry) — per-paper

Resilience pattern: returns None on failure rather than raising — so one bad entry doesn't kill an entire batch of 100 papers.

It calls 5 field extractors:

ExtractorWhat it doesEdge case handling
_get_arxiv_idParses <atom:id> URL, returns last path segmentReturns None if missing → entry skipped
_get_textGeneric text extractor for any pathclean_newlines=True collapses line breaks (used for title/abstract)
_get_authorsIterates <atom:author>, reads each <atom:name>Skips empty names
_get_categoriesIterates <atom:category>, reads term attributeSkips entries without term
_get_pdf_urlFinds <atom:link type="application/pdf">Forces HTTPS — rewrites http://arxiv.org/ → https://arxiv.org/

Result is assembled into an ArxivPaper Pydantic model.

Layer 5 — PDF Download

Separate from metadata fetching — only triggered when a caller explicitly wants the PDF.

download_pdf(paper, force_download=False) — public entry

Cache-first strategy:

  1. If paper.pdf_url is empty → return None
  2. Compute local cache path via _get_pdf_path
  3. If file exists and force_download=False → return cached path without network call
  4. Otherwise delegate to _download_with_retry

_get_pdf_path(arxiv_id) — filesystem-safe naming

Replaces / with _ in the ID. Important for old-style IDs like math.GT/0309136 that contain a slash — without this, you'd get pdf_cache_dir/math.GT/0309136.pdf, treating part of the ID as a subdirectory.

_download_with_retry(url, path, max_retries=3) — streaming + backoff

Streaming download

Uses client.stream(...) and response.aiter_bytes():

async with client.stream("GET", url) as response:
    with open(path, "wb") as f:
        async for chunk in response.aiter_bytes():
            f.write(chunk)

This keeps memory usage flat regardless of PDF size (a 50MB PDF won't load 50MB into RAM).

Retry policy — linear backoff

  • Attempt 1 fails → wait 5s
  • Attempt 2 fails → wait 10s
  • Attempt 3 fails → raise typed exception

Distinguishes failure types

Error typeAfter exhausting retries
httpx.TimeoutExceptionPDFDownloadTimeoutError
httpx.HTTPErrorPDFDownloadException
Anything elsePDFDownloadException (immediately, no retry)

Cleanup: if all retries fail, the partially-written file is deleted via path.unlink().

Key Design Patterns

  1. DIDependency Injection — ArxivSettings is passed in, not imported globally. Makes testing and reconfiguration trivial.
  2. LazyLazy initialization — pdf_cache_dir directory is only created on first PDF access via @cached_property.
  3. ResilientResilient parsing — bad XML entries are skipped (logged), not raised. One malformed paper doesn't kill a 100-paper batch.
  4. Typed ErrorsTyped exception hierarchy — callers catch ArxivAPIException / PDFDownloadException without depending on httpx.
  5. Cache-firstCache-first downloads — checks disk before going to the network, with a force_download escape hatch.
  6. StreamingStreaming downloads — constant memory regardless of PDF size.
  7. SecurityHTTPS enforcement — _get_pdf_url rewrites http:// to https:// so the downloader can never fall back to plaintext.
  8. SafetyFilesystem-safe IDs — _get_pdf_path sanitizes legacy IDs like math.GT/0309136.
