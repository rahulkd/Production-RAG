What is uv.lock?
uv.lock is the lockfile generated by uv (a fast Python package manager). It's the equivalent of pip freeze > requirements.txt but more precise and cross-platform.

Who generates it: You do, on your dev machine — not Docker.


uv sync        # installs deps AND generates/updates uv.lock
uv lock        # only updates uv.lock without installing
It records the exact resolved version + hash of every package (including transitive dependencies):


# pyproject.toml says:    fastapi>=0.115.12   (flexible)
# uv.lock pins it to:     fastapi==0.115.12   (exact, with sha256 hash)
You commit uv.lock to git so everyone (and every Docker build) gets identical installs.

How the Dockerfile uses it
No — uv.lock is NOT generated during docker build. It is copied in.


# Stage 1: build env
FROM ghcr.io/astral-sh/uv:python3.12-bookworm AS base

COPY pyproject.toml uv.lock ./          # ← lock file copied FROM your machine

RUN uv sync --frozen --no-dev           # ← --frozen means "read lock, don't update it"
                                        #    --no-dev skips test/lint tools

# Stage 2: lean final image
FROM python:3.12.8-slim AS final        # ← smaller base (no uv, no build tools)
COPY --from=base /app /app              # ← only copies the installed .venv
CMD ["uvicorn", ...]
This is a multi-stage build — the first stage does the heavy lifting (installing uv and all packages), the second stage copies only the result into a slim image. Your final container doesn't have uv, compilers, or dev tools in it.

The full flow

Developer machine                    Docker build
──────────────────                   ────────────
pyproject.toml  ──┐
                  ├─── uv sync ──▶  uv.lock  (committed to git)
                  │
                  └─── both COPY'd into image ──▶ uv sync --frozen
                                                   (installs exact versions)
                                                   ──▶ .venv/
                                                   ──▶ final slim image
Key flags explained
Flag	Meaning
--frozen	Fail if uv.lock would need updating — ensures reproducibility
--no-dev	Skip the [dependency-groups] dev packages (pytest, ruff, mypy etc.) — no test tools in prod
UV_COMPILE_BYTECODE=1	Pre-compiles .py → .pyc at build time for faster startup
UV_LINK_MODE=copy	Copies files instead of hard-linking (required when cache and install are on different filesystems in Docker)
The --mount=type=cache line caches downloaded packages between builds so repeat docker build runs don't re-download packages from the internet.
