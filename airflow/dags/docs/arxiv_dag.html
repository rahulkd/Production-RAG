Module 2 — Task Functions (arxiv_ingestion/tasks.py)

Shared Infrastructure: get_cached_services()

@lru_cache(maxsize=1)
def get_cached_services():
    arxiv_client = make_arxiv_client()
    pdf_parser = make_pdf_parser_service()
    database = make_database()
    metadata_fetcher = make_metadata_fetcher(arxiv_client, pdf_parser)
    return arxiv_client, pdf_parser, database, metadata_fetcher
Why this matters: Without caching, every task invocation would reload Docling's PyTorch models (~seconds + GB of RAM). @lru_cache(maxsize=1) ensures one initialization per Airflow worker process, reused across tasks in the same DAG run.

Async/Sync Bridge: run_paper_ingestion_pipeline(...)

Airflow runs synchronous Python callables, but the underlying pipeline is async. This wrapper:

  1. Gets cached services
  2. Opens a DB session via context manager
  3. awaits metadata_fetcher.fetch_and_process_papers(...)

The synchronous Airflow task uses asyncio.run(...) to invoke it.

The 6 Tasks

Task 1: setup_environment — health check

  • Triggers service initialization (warms the lru_cache)
  • Runs SELECT 1 against the DB to verify connectivity
  • Logs arXiv base URL + PDF parser readiness
  • Raises a typed exception if anything fails → blocks the rest of the DAG

Task 2: fetch_daily_papers — main work

Key insight: it processes papers from execution_date - 1 (yesterday)

execution_date = context["ds"]                    # "2025-08-08"
target_dt = execution_dt - timedelta(days=1)      # "2025-08-07"
target_date = target_dt.strftime("%Y%m%d")        # "20250807"

Why yesterday? arXiv papers submitted today aren't fully indexed yet — fetching with a 1-day lag gives a stable view.

Then:

  • Calls asyncio.run(run_paper_ingestion_pipeline(target_date=..., max_results=10, process_pdfs=True))
  • Pushes results to XCom via context["task_instance"].xcom_push(key="fetch_results", value=results) — so downstream tasks can read them

Task 3: process_failed_pdfs — retry placeholder

  • Pulls XCom: xcom_pull(task_ids="fetch_daily_papers", key="fetch_results")
  • Iterates over the errors list from the main fetch
  • Currently logs each error (TODO: implement actual retry)
  • Returns count of errors investigated

Task 4: create_opensearch_placeholders — Week 2 placeholder

  • Reads papers_stored count from XCom
  • Logs what would be indexed (actual indexing comes in Week 3+)
  • Demonstrates the future plug-point for the search backend

Task 5: generate_daily_report — aggregated summary

Pulls XCom from all three previous tasks:

  • fetch_daily_papers → metrics
  • process_failed_pdfs → retry stats
  • create_opensearch_placeholders → indexing stats

Builds a structured report dict and logs a human-readable summary block.

Task 6: cleanup_temp_files — BashOperator

find /tmp -name "*.pdf" -type f -mtime +30 -delete 2>/dev/null || true
  • Removes PDFs older than 30 days
  • || true keeps the task green even if no files match

Data Flow via XCom

XCom is Airflow's inter-task message-passing mechanism — keys/values are stored in the metadata DB.

fetch_daily_papers
       │ xcom_push(key="fetch_results", value=results)
       │
       ├──► process_failed_pdfs
       │      └─ xcom_pull(task_ids="fetch_daily_papers", key="fetch_results")
       │      └─ returns retry stats (implicit XCom push of return value)
       │
       └──► create_opensearch_placeholders
              └─ xcom_pull(task_ids="fetch_daily_papers", key="fetch_results")
              └─ returns indexing stats
                     │
                     ▼
              generate_daily_report
                     └─ xcom_pull(task_ids="fetch_daily_papers")
                     └─ xcom_pull(task_ids="process_failed_pdfs")
                     └─ xcom_pull(task_ids="create_opensearch_placeholders")

Key Design Patterns

  1. SeparationDAG / task code separation — DAG file stays small and declarative; logic lives in arxiv_ingestion/tasks.py
  2. Cachinglru_cache for service init — Docling models loaded once per worker process
  3. BridgeAsync/sync bridge — asyncio.run() lets sync Airflow tasks consume the async pipeline
  4. StabilityDay-lag fetching — process execution_date - 1 for stable arXiv data
  5. MessagingXCom for task chaining — structured data passing, not implicit globals
  6. TopologyFan-out / fan-in graph — retry + indexing run in parallel after fetch, both feed report
  7. ScheduleCron with weekday filter — 1-5 skips weekends without separate weekend logic
  8. Concurrencymax_active_runs=1 — serializes runs to prevent DB write conflicts
